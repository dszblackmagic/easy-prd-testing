# Easy PRD Testing v0.1.3

## 更新亮点

- 新增面向静态页面与动态应用的浏览器执行协议，强化侦察、定位、断言、证据和清理闭环。
- 优化执行前环境识别与服务归属判断，减少可安全推导信息的重复询问。
- 项目仓库正式迁移至 `CoffeeCheese/easy-prd-testing`，同步更新安装、升级与插件元数据链接。
- 新增双升级清单通道，在使用新仓库地址的同时保持 v0.1.2 客户端连续升级。

## 更新内容

### 浏览器测试执行

- 区分静态 HTML、本地动态应用和远程测试环境，优先通过只读探测判断服务状态与页面就绪条件。
- 首次浏览器执行遵循“进入、就绪、侦察、定位、操作、断言、分类、证据、清理”闭环。
- 使用可观察条件和 web-first assertion 判断页面就绪，不将固定等待或 `networkidle` 作为唯一依据。
- 在导航前注册 Console、页面错误、失败请求和关键响应观测，并在失败清理前保存真实产生的证据。
- 保留 `agent-browser` 默认执行方式，同时兼容 Playwright Test 与 DevTools 诊断升级。

### 执行记录与服务生命周期

- 统一 `passed`、`failed`、`blocked`、`untested`、`pending-confirmation` 五种执行状态。
- 补充目标类型、服务状态、服务归属、页面就绪、定位器风险、观测结果与清理责任记录。
- 已存在或由用户管理的服务默认保持运行；远程环境不执行启动、重启或停止操作。
- 修复执行记录模板的 Markdown 表格结构，并保持汇总状态与优先级记录一致。

### 仓库地址迁移

- README 中英文版、Release 徽章、安装提示词、Star 和 Issue 链接切换到新仓库地址。
- Codex Plugin 的主页与仓库元数据切换到 `CoffeeCheese/easy-prd-testing`。
- Release 包、更新清单与可信下载地址使用新仓库命名空间。
- 官方 Git 克隆识别同时兼容新地址和仓库更名前的历史地址。

### 升级兼容与发布

- `latest-v2.json` 作为新客户端的升级清单，所有公开链接均指向新仓库地址。
- `latest.json` 继续作为 v0.1.2 客户端兼容通道，借助 GitHub 仓库重定向完成升级。
- 新客户端在迁移版尚未提供 `latest-v2.json` 时，会安全回退到历史兼容清单。
- 发布工作流同时验证并上传版本压缩包、`latest.json` 和 `latest-v2.json`。
- 本文件是 `v0.1.3` GitHub Release Notes 的唯一来源。

## 升级说明

v0.1.2 用户无需修改现有安装地址，只需向 AI 表达“升级版本”“更新 Skills”或相近含义，即可升级到 v0.1.3。升级完成后，建议新建 AI 会话或重新加载当前工具的 Skills / Plugin，使新版本规则完整生效。

使用 Git 克隆安装的用户也可以主动将 `origin` 更新为：

```text
git@github.com:CoffeeCheese/easy-prd-testing.git
```
